# Settings

One Settings window for R5. Existing preference programs stay separate and keep their own files.

## Host

`Settings` is a single-launch preference (`application/x-vnd.R5OS-Settings`). The window is a sidebar, a search field, and one content deck (`BCardLayout`). Changing page does not create a new window. The regular image and the minimum image both install this program, the fonts and look modules, and `libr5icons.so`. Settings links that shared library.

This frame is fixed (`AGENTS.md`). The picture it follows is `docs/design/settings-mockup/`. The list shows Home, then the categories. Only the category of the open page is unfolded. Search filters the list. The list starts under the tab and runs down to Search. The heading is one card beside the list, and that page's icon sits at the right of the title. The page content is under the heading. When that content is taller than the area, the page scrolls and the scrollbar is visible. Search stays under the list. The bottom row is the lock, Revert, and Defaults. There is no Back button and no Home button. Home is the first list item. The lock calls `r5_button_set_lock()` so it matches the height of Revert and Defaults. The lock does not get the preferences wrench. The lock is closed (`R5_ICON_LOCKED`, Haiku `Action_Logout`) until an administrator password opens it (`R5_ICON_UNLOCKED`, Haiku `Action_Login`). One open lock covers every page in this window that requires an administrator, for the same few minutes as the other locked preferences. An administrator account starts open. While a page is locked its controls are gray and nothing is written. The list on that page still scrolls. Search and the sidebar stay usable. The window opens at 1030 by 610. The list and Search are 200 wide. A home card is at least 280 wide. The shortest size is 910 by 560. The list scrollbar is there only when the items are taller than the list. A category card lights up under the pointer and looks pressed while the mouse button is held down.

A box title written as ordinary text is bold. That is the screen size (or Display) and Workspaces, Applications, Menu, Window, Preview, Device, and R5 Operating System. A checkbox that sits on the box border is bold when it is Enable notifications or Enable virtual memory. A menu on the box border stays in the plain font.

A change is applied as soon as it is made. Revert restores the values from when the page was opened and applies them. Defaults restores a page's factory setup and applies it. Desktop and Deskbar and Notifications have a factory setup. Defaults stays disabled on the others.

A new page adds its icon signature in `module_icon()` in `SettingsWindow.cpp`. Home uses the R5 wave pebble (the same HVIF as About R5). The Settings application icon is that pebble with the preferences wrench. Information uses the About icon. Every one of those page icons, and the icons on the home cards, has the Haiku preferences wrench drawn on top. The wrench is the unmodified Haiku file `overlay-prefs.hvif`. It belongs to this Settings application and its modules. About R5 is not a settings module and does not get the wrench.

Display is a page under System. The subtitle is "Screens, resolution, and workspaces". The separate Screen program stays installed. The page is locked until an administrator opens the lock. The arrangement is `BScreenArrangement` (`docs/LIBR5.md`), which draws each screen with `r5_screen_draw()`. With one screen the tile is centered, it cannot be dragged, and Identify, the screens menu, Scale, Rotation, Main screen, and Mirror or Extend stay off the page. The name comes from `BScreen::GetMonitorInfo()` (vendor and name). When that is empty the name is Screen. The box title is "Screen – " plus that name. The two boxes use the same light fill as the Information tiles: the panel background mixed toward the document background by 100. Their border is `tint_color()` of the panel with `B_DARKEN_2_TINT` (`#c4c4c4`). The arrangement picture uses the list background mixed toward `B_CONTROL_HIGHLIGHT_COLOR` by 18, and that mix at 48 for the border (`#f3f6fb` and `#dbe3ef`). Hint text (`#64748b`) is the document background mixed toward the document text by 140. The workspace sentence (`#475569`) is that mix at 160. The dark frame around a workspace cell (`#3b3f46`) is the panel mixed toward the document text by 200. The selected screen and the current workspace use `B_STATUS_BAR_COLOR`. Colors is shown only when the screen offers more than one depth. Resolution marks the largest mode "(recommended)". Workspaces change the column and row count immediately. A click on a cell calls `activate_workspace()`. Resolution, colors, and refresh wait for Apply. Apply asks to keep the picture. After 12 seconds without a choice the previous picture returns. Revert restores the mode and the workspace layout from when the page was opened. Notifications and Desktop and Deskbar still call `r5_screen_draw()` themselves.

Information is a page under System. It shows one device card, six tiles, one Copy details button, and a footer. The device card has the computer's name, a Rename… link, and the R5 version. The model line is shown only when a program can read it. It is left out: the kernel logs the vendor and product in `smbios_scan`, and `generic/smbios` only offers `match_vendor_product()` to other kernel code. A program has no public way to read those two strings. Showing the line needs a small additive call that returns them. That call is not part of this page, and the kernel is not changed. Rename… writes the name with `sethostname()`, the call Network already uses. That call stores the name in the existing network hostname file (`B_SYSTEM_SETTINGS_DIRECTORY` / `network/hostname`), which is what `gethostname()` reads, so the new name shows up without a restart. The name may use letters, digits, and `-`, at most 63 characters, and it does not start or end with `-`. The link stays grey until the lock is open. Copy details copies every line on the page. The tiles are Processor, Memory, Storage, Graphics, Display, and Running for. Storage is the boot volume. There is no device id. The build date is the Europe/Amsterdam time of the image jam. Graphics says the desktop is drawn by the processor, because the app server does not use the GPU yet. Memory in use and Running for refresh every 2 seconds while the page is visible. The quiet text (`#64748b` in the mockup) is a mix of the document background and the document text, amount 140. The tile detail (`#475569`) is the same mix at amount 160. The model line, when it exists, would use that mix at amount 190 (`#334155`). Tile fill (`#e4e4e4`) is a mix of the panel background and the document background, amount 100: a darkened panel tint was much darker than the mockup on the Haiku panel grey. Borders are `tint_color()` of the panel background with `B_DARKEN_2_TINT` (`#c4c4c4`). The usage track (`#c9cfd6`) is the tile fill mixed with the document text, amount 40, so it stays visible in dark mode. The Rename… and What's new links are underlined, as in the mockup. The usage fill is `B_STATUS_BAR_COLOR`, the blue of a selected row in the list. The window grey stays `B_PANEL_BACKGROUND_COLOR`.

The sidebar and the home cards are filled from the module list. Pages under a category are alphabetical by name. Information stays first under System. A category card and the subtitle of an open page use that page's description. Leave that order, and these five descriptions, as they are until the user explicitly asks to change them. Another Settings task does not include reordering the list or rewriting these lines. Information is "View system details". Virtual memory is "Extra memory stored on disk". Wallpaper is "Set the background of your desktop". Desktop and Deskbar is "Adjust desktop and Deskbar settings". Notifications is "Manage alerts and notifications". Category names for `personalization`, `system`, `devices`, `network`, and `accounts` live in one table in `SettingsWindow.cpp`. Personalization's summary is fonts, look and feel, wallpaper, and the Deskbar. System's summary is display, sound, notifications, virtual memory, and this computer. Devices' summary is keyboard, mouse, touchpad, printers, and Bluetooth. Network's summary is wired and Wi-Fi connections, and network shares. Accounts' summary is the people who use this computer, and how they sign in. A module with another category id is still shown. A category page uses the same cards as Home and does not repeat the category summary under the title. The sixth place on Home is Recently changed: the last three pages that were changed, newest first. Before any change it says "Nothing changed yet". Those names are stored in `~/config/settings/r5-settings/settings-window`. The lock, Revert, and Defaults sit on the bottom row.

Manrope Regular and Bold are the default plain and bold fonts when no font settings are saved. The fixed font stays Noto Sans Mono. The files are installed in `data/fonts/ttfonts`. Settings still selects Manrope for its own window, and falls back to the system font if that family is missing. The page title is the bold face, eight points above the bold system size.

Wallpaper is the Backgrounds window, rewritten as this page. The picture, placement, icon-label outline, and desktop color sit on the left. The preview sits on the right. A change writes `be:bgndimginfo` on the Desktop folder, or on a folder, then asks Tracker to restore the picture. The workspace menu on the page chooses the current workspace, every workspace, or a folder. The desktop color is `BScreen::SetDesktopColor`. The separate Backgrounds program stays on the disk and is not a page in this window.

Desktop and Deskbar is a page under Personalization. Each change messages the running Deskbar (`application/x-vnd.Be-TSKB`) immediately, including the icon-size slider and the application checkboxes. It does not write `~/config/settings/deskbar/settings` itself. Deskbar writes that file when it quits. Auto-hide is the exception Deskbar already had: that one is written immediately. The clock stays out of this page. The separate Deskbar preferences program stays installed. Where the bar sits is a picture of the screen: the top and bottom edges, the four corners, and a taller bar on the left or right top for the application list. Show applications follows that picture for the top corners. Applications and Menu sit next to each other, and Window is underneath both, so the page fits in the window.

The page reads that settings file for the application list, the icon size, and the recent counts, because Deskbar has no public getter for them. The place and the three window flags come from `BDeskbar` when Deskbar is running. Sort, Tracker first, the expanders, and hide names are toggles: a change sends one message only when the value differs from what this page last sent, starting from the file read at load. If the old preferences window changed Deskbar's memory in this session and Deskbar has not quit, that one toggle can land on the wrong side. Icon size (`be:value` times 8) and the recent counts are absolute. Location uses `BDeskbar::SetLocation`. Top and bottom are always expanded. Left bottom and right bottom are not. Show applications is only offered for left top and right top. Always on top is sent before auto-raise, and auto-raise is not sent while always on top is on. A recent count of 0 is stored by Deskbar as off. Defaults applies Deskbar's own defaults immediately. Revert applies the values from when the page was opened. Edit in Tracker opens `B_USER_DESKBAR_DIRECTORY` with `B_REFS_RECEIVED`. The count fields are `BSpinner`. The class lives in `libbe`. The header is private, so the Settings Jamfile has `UsePrivateHeaders interface`, the same way Deskbar's own window includes it. "Expand new applications" is indented by 20 pixels under "Show application expander". That indent is a real width. `B_USE_DEFAULT_SPACING` is a negative layout constant and must not be passed to `CreateHorizontalStrut()`.

Notifications is a page under System. The card on that category uses the page description. The icon is the Notifications program (`application/x-vnd.Haiku-Notifications`), with the same wrench as the other Settings icons. A change writes `~/config/settings/system/notifications` immediately. That is the file the notification server reads. The page does not keep a second copy under `r5-settings`. The directory `settings/system` is created for the signed-in user by `r5-desktop` before the desktop starts. The image ships `config/settings` as root, mode 0755, so a new directory there was permission denied and the example was never sent. Enable notifications and Applications sit next to each other and share the same height, so the page fits in the window. Where the message appears is a screen picture. The four corners place it there. The bar on that screen follows the running Deskbar and means Follow Deskbar. Width, timeout, and position send one sample notification after a successful write. Enabling notifications, and muting an application, do not. Defaults restores enable, a 10 second timeout, a width of 300, and the lower right. It leaves the application list and a stored icon size alone. Revert restores the values from when the page was opened, including the list. The separate Notifications program stays installed.

Virtual memory is a page under System. It requires the lock. The icon is the VirtualMemory program (`application/x-vnd.Haiku-VirtualMemory`), with the same wrench. A change writes `/boot/system/settings/kernel/drivers/virtual_memory` immediately, in the same text the kernel already reads. That takes effect on the next start. Swap can be on or off, automatic or a chosen size on a chosen volume. Turning swap off asks first. Defaults is swap on, automatic, on the boot volume. Revert restores the values from when the page was opened. The separate VirtualMemory program stays installed. While the lock is closed the controls are gray and the file is not written.

Search compares the module name, description, keywords, and category label. Clearing Search shows the whole list again, including the category that was unfolded.

Leaving a page does not ask, because the change is already applied.

Page changes are immediate. There is no compositor, so the window does not animate a transition (`docs/LOOK.md`).

## Modules

The contract is `distro/settings/SettingsModule.h`, version 2. `distro/settings/ModuleAPI.md` is the developer note.

`SettingsManager` loads add-ons from the `Settings` directories under the system and user add-ons paths, including `non-packaged`. It checks `settings_api_version()` before `instantiate_settings_module()`. A wrong version is not loaded. Images stay loaded until the modules are deleted, then `unload_add_on` runs.

Fonts (`settings_fonts`) and Look and Feel (`settings_look`) are pages under Personalization. There is no Appearance page and there are no tabs. Fonts uses the font rows from the separate Appearance program. Its subtitle is "Change the default fonts". Antialiasing is a box on that page. Look and Feel uses the decorator, control look, and arrow style from that program. Its subtitle is "Change the default decorator and colors". Colors is a box on that page. A change is applied at once, through the same calls the separate program uses. Neither page writes a settings file of its own. Revert and Defaults are the window buttons. The pages are not locked. The separate Appearance program stays installed. Both pages use that program's icon. The other four category descriptions stay as they are.

## Legacy programs

`LegacyPages.cpp` is a table of programs that already exist: Sounds, Keymap, Input, Bluetooth, Printers, Network, and Users & Accounts. Each row is a page with an Open button. `BRoster::Launch` starts that program. Nothing is embedded, because those programs are windows, not views we can reuse. Appearance, Screen, Backgrounds, the Deskbar preferences program, Notifications, and VirtualMemory stay installed and are not in this table.

Adding a row there is how an old preference shows up before it is rewritten. A new native page does not need a row and does not need a change to the window.

## Storage and the administrator lock

New R5 values are `BMessage` files under `~/config/settings/r5-settings/<module id>`. The id is checked so one module cannot name another's file. Haiku files such as `Appearance`, `Keyboard`, and `Network` are not moved.

`SettingsHost::AdminChangeAllowed()` calls `r5_admin_change_allowed()` from Users & Accounts. The window refuses the write when the module says `RequiresAdmin()` and that call is false. The module repeats the check in `SaveSettings()` before a privileged write. The lock button uses `r5_admin_query()`, `r5_admin_prompt_unlock()`, and `r5_admin_relock()`. The picture is `r5_button_set_lock()` in `libr5icons.so`.

## Not in this foundation

Power, storage, sharing, sign-in options, permissions, installed applications, and default applications have no page yet. Wi-Fi stays inside the existing Network preferences. Catalogs are not wired, so the strings are English.
