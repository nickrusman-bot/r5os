Interface guidelines

Making it look like R5

How an R5 window is put together: Haiku controls on the panel, a card only where something stands on its own, one main action, sharp icons, and changes that apply at once. These are the rules R5's own windows follow.

Forms

  • The window background is the panel color, B_PANEL_BACKGROUND_COLOR. Do not put a white card behind a form.
  • Labels share one column and are right-aligned. Values share the next column and start on the same line.
  • A label and its field share one row and its vertical center. A text field is one line high.
  • A grid row does not grow with the window or with a tall neighbor such as a picture or a list. Extra room is glue outside the form.
  • Buttons that belong together sit on one row.
Hiding a column. Use the layout item's SetVisible() after the window is shown. Before Show(), IsHidden() follows the window, so a Hide() in the constructor never runs.

Cards

A BCard holds something that stands on its own: a heading, a summary, an account. A form stays on the panel. A page of choices uses BActionCards; the top of a page uses a BPageHeader.

Buttons

  • One main action per window, as a BAccentButton: Sign in, Unlock, Install. Everything else is a plain BButton.
  • An icon button on a row of text buttons has their height: use r5_button_set_icon() with that height.
  • A symbol before a label, such as Restart or Shut down, is a line glyph.

Icons

  • Use Haiku's own icons. A glyph is only for a small symbol Haiku has no icon for.
  • Render an icon at the size it is shown, and draw it pixel for pixel. A stretched bitmap gets jagged edges; BIconView does it right.
  • The preferences wrench is only for the Settings application and the pages inside it.

Settings pages

  • A change is applied at once. There is no Save button.
  • Revert puts the page back to the values from when it was opened, and applies them. Defaults puts it back to its factory setup. Defaults stays disabled on a page that has none.
  • A page that needs an administrator is gray, and writes nothing, until the lock is opened. One unlock covers every such page.
  • A setting a person changes for themselves is written in their own home, never by a system service.

People and accounts

  • A list of people is two lines: the name in bold, then the username and the role. Use BUserListItem.
  • The signed-in person can edit their own name, email, picture and password while the computer is locked. The lock is for the computer and for other people.
  • Do not hardcode a home folder. Use find_directory() or getpwuid().

Words

  • The product is R5 Operating System, short R5. Not Haiku, not BeOS, not R5OS in text people read.
  • Say what the user gets, in plain language. A message says what happened and what to do, for example "That password is not right." rather than an error code.
  • The font is Manrope, the system font. Use the system font sizes, so a larger font scales the window.
