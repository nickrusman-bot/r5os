Settings add-on

Settings modules

A page in Settings is an add-on. Settings finds it at start, lists it under its category, and shows its view when someone opens it. A new page needs no change to the Settings window. Fonts and Look and feel are built this way.

Declared inSettingsModule.h (in the R5 source, distro/settings; not yet in a development package)
API versionkSettingsApiVersion = 2
Build ruleAddon
Contractdistro/settings/ModuleAPI.md, docs/SETTINGS.md
Built for one version. Settings loads a module only when settings_api_version() returns the version Settings was built with. A module for another version is skipped, with a line in the syslog that starts with settings:. A new call is added only at the end of the class, with a new version number.

Where it goes

Install the add-on in a folder named Settings in one of the add-ons folders. Settings reads all four.

FolderFor
/boot/system/add-ons/SettingsPages that ship with R5
/boot/system/non-packaged/add-ons/SettingsFor every account, outside a package
/boot/home/config/add-ons/SettingsOne account, from a package
/boot/home/config/non-packaged/add-ons/SettingsOne account, outside a package

A module that fails to load does not stop the others. If two modules have the same identifier, only one is loaded.

Entry points

two exported functions

Both are extern "C", exported, and not inline. Include SettingsModule.h only, not the Settings window or its host.

#include "SettingsModule.h"

extern "C" _EXPORT int32
settings_api_version()
{
	return kSettingsApiVersion;
}

extern "C" _EXPORT SettingsModule*
instantiate_settings_module()
{
	return new ExampleModule();
}

SettingsModule

class
Declared inSettingsModule.h
Derived fromnone
First userFonts (settings_fonts)

One page. Derive from it and return a new one from instantiate_settings_module().

What the page is

virtual const char* Identifier() const = 0;

A stable id: letters, digits, ., _ and -, at most 64 characters. It is also the name of the page's settings file.

virtual const char* Name() const = 0; virtual const char* Description() const = 0; virtual const char* Keywords() const;

The name in the list, the subtitle under the page title (and the line on the category card), and extra words for Search. Search compares all three and ignores case.

virtual const char* Category() const = 0;

One of personalization, system, devices, network and accounts. Another id is listed too, with the id as its label. Pages under a category are in alphabetical order.

virtual bool RequiresAdmin() const;

True for a page that changes the whole computer. The page is gray, and nothing is written, until the lock is open. See The lock.

virtual bool CanSave() const;

False for a page that only opens an existing preferences program, which keeps its own file.

The view

virtual BView* CreateView(SettingsContext* context, BRect frame) = 0;

The page content, shown under the subtitle. The window owns the view and deletes it; the module must not. Keep a pointer only if the page has to update after Revert, and clear it in the view's destructor. When the view is taller than the space, the page gets a scroll bar. Returning NULL shows a short error; the rest of Settings stays open.

Values

virtual status_t LoadSettings(SettingsContext* context) = 0;

Reads the current values. Keep a copy: that is what Revert goes back to.

virtual status_t SaveSettings(SettingsContext* context) = 0;

Writes the values. The window calls it as soon as the page calls NotifyChanged(). There is no Save button.

virtual status_t RevertSettings(SettingsContext* context) = 0;

Puts back, and applies, the values from when the page was opened, also after they were already written.

virtual bool CanApplyDefaults() const; virtual status_t ApplyDefaults(SettingsContext* context);

Added in version 2. CanApplyDefaults() is true only when the page has a factory setup; otherwise Defaults stays disabled. ApplyDefaults() writes and applies that setup.

virtual bool IsModified() const; virtual int32 ApiVersion() const;

Whether the values differ from when the page was opened, and the version the module was built for. Leave ApiVersion() as it is.

SettingsContext

class
Declared inSettingsModule.h
Made bythe Settings window

What the window offers a page. The module receives it; it does not make one.

virtual status_t ReadSettings(const char* moduleId, BMessage& settings) = 0; virtual status_t WriteSettings(const char* moduleId, const BMessage& settings) = 0;

One flattened BMessage per page, in ~/config/settings/r5-settings/<identifier>. A missing file is B_ENTRY_NOT_FOUND: use the defaults.

virtual void NotifyChanged(const char* moduleId) = 0;

Call it after the person changes a value. The window then calls SaveSettings().

virtual bool AdminChangeAllowed() const = 0;

True while the lock is open. This is r5_admin_change_allowed().

virtual status_t OpenPage(const char* moduleId) = 0; virtual status_t LaunchLegacy(const char* signature) = 0;

Open another page, or start a preferences program by its signature.

virtual void Log(const char* message) = 0;

A line in the syslog, after settings:.

Where the values go

  • A new setting: use ReadSettings() and WriteSettings().
  • A setting the system already reads: write that existing file, and keep no second copy. Notifications writes ~/config/settings/system/notifications.
  • A running program: send it a message. Desktop and Deskbar messages the running Deskbar and does not write Deskbar's file.

The lock

When RequiresAdmin() is true, the window refuses to save while AdminChangeAllowed() is false. A check box in the page is not the check: call AdminChangeAllowed() again in SaveSettings() before writing a value for the whole computer. For a driver setting, the clock or the time zone, use the administrator calls in R5UI.h; the page itself runs as the signed-in account.

Example

class ExampleModule : public SettingsModule {
public:
	const char* Identifier() const { return "example"; }
	const char* Name() const { return "Example"; }
	const char* Category() const { return "system"; }
	const char* Description() const { return "Try out a setting"; }

	BView* CreateView(SettingsContext* context, BRect frame);

	status_t LoadSettings(SettingsContext* context)
	{
		if (context->ReadSettings(Identifier(), fOpened) != B_OK)
			fOpened.MakeEmpty();		// no file yet: the defaults
		fCurrent = fOpened;
		return B_OK;
	}

	status_t SaveSettings(SettingsContext* context)
		{ return context->WriteSettings(Identifier(), fCurrent); }

	status_t RevertSettings(SettingsContext* context)
	{
		fCurrent = fOpened;
		return context->WriteSettings(Identifier(), fCurrent);
	}

private:
	BMessage fOpened;
	BMessage fCurrent;
};
