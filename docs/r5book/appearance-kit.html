libr5ui.so

The Appearance Kit

The parts R5's own windows are built from: Settings, About, Display, Sign in and the lock screen. All classes are in namespace BAppearanceKit, follow the system colors and font size, and can be archived.

NamespaceBAppearanceKit
Librarylibr5ui.so (links libr5icons.so)
Sourcedistro/ui
Which class for whatdocs/APPEARANCE-KIT.md
Not Haiku's BCardView. BCard is a rounded panel with a layout, not a stack of pages. A stack of pages is still Haiku's BCardView / BCardLayout.

BAccentButton

class
Declared in<AccentButton.h>
Derived fromBButton
First userSign in, Unlock on the lock screen

The one main action of a window, filled with the selection blue, with a bold label one step larger than body text. It is a BButton: the message, the target, MakeDefault() and Enter work as usual. It is as wide as its label; for the full row, set an explicit maximum width of B_SIZE_UNLIMITED.

Use it for

The single action the window is for: Sign in, Unlock, Install.

Not for

Every button on a row. Restart, Cancel and the like stay plain BButtons.

BAccentButton(const char* name, const char* label, BMessage* message = NULL);

38 pixels high at a 12 point font. The label is white on a dark accent and black on a light one.

BAppearanceKit::BAccentButton* signIn = new BAppearanceKit::BAccentButton(
	"signin", "Sign in", new BMessage(kAttemptLogin));
signIn->SetExplicitMaxSize(BSize(B_SIZE_UNLIMITED, B_SIZE_UNSET));
window->SetDefaultButton(signIn);

class

First userSettings home; R5 Hub and Store next

A card the user clicks: an icon, a title, a summary of at most two lines and small tags. It follows the pointer, the pressed button and the keyboard focus. A click on the card, Space or Enter calls Invoke(); a click on a tag sends the tag message.

Use it for

A start page of choices: Settings home, the R5 Hub and Store front page.

Not for

A form. The card does not hold other views.

The summary wraps to two lines; the second ends with an ellipsis.

int32 AddTag(const char* label); void RemoveAllTags(); int32 CountTags() const; void SetTagColor(rgb_color tint); void SetTagMessage(BMessage* message);

A click on a tag sends the tag message with int32 "be:tag" and "be:label".

void SetHighlighted(bool on);

Draws the card as if the pointer were on it, for example for a search match.

BAdminLockBar

class
Declared in<AdminLock.h>
Derived fromBGroupView
First userTime, Screen, Network, Printers, Repositories, VirtualMemory, Users, Settings; Device Manager; Media (the calls, not the bar)

The lock for machine settings. A program runs as the signed-in person; a change that needs an administrator goes to Sign in (Login), which checks the grant and makes the change. The bar is a label and an Unlock button. While it is locked, the views in its window are gray; an administrator starts unlocked, and one unlock opens the program for five minutes. AdminLockBar is a typedef for this class, the name the preferences have always used.

It was compiled into each preference under GPL-3.0-or-later. Since November 2026 it is part of libr5ui.so and MIT, so any program can link it. Login, the side that checks the password, stays GPL and is reached only by messages.

Use it for

A window that changes the whole computer: the clock, the screen mode, network, printers, drivers.

Not for

The person's own settings. Those need no administrator and stay unlocked.

BAdminLockBar();

Put it in the window's bottom row. It asks Login when it is attached and watches the grant.

void SetExempt(BView* view, bool exempt);

Keeps one view usable while the lock is closed, for example the person's own account card in Users.

bool AcceptsInput(BHandler* target) const;

Whether a click or key for target goes through now.

status_t r5_admin_query(bool& administrator, bool& unlocked); bool r5_admin_change_allowed();

Asks Login. unlocked is true for an administrator or while a grant runs. Both are false when Login cannot be asked.

void r5_admin_prompt_unlock(BMessenger target); status_t r5_admin_unlock(const char* name, const char* password, BString& error); status_t r5_admin_relock();

The unlock window, the same without a window, and ending the grant. On success the window sends kMsgAdminLockChanged to target. The password is not logged.

status_t r5_admin_set_clock(unsigned long seconds); status_t r5_admin_set_timezone(int32 offset, const char* name); status_t r5_admin_set_clock_gmt(bool gmt);

The clock and the time zone, for Time and Settings.

status_t r5_admin_set_driver_blocked(const char* driver, bool blocked, BString& error);

Turns a packaged driver under /boot/system/add-ons/kernel/ off or on for the next start. Login refuses drivers the system needs to start. Device Manager uses it.

bool r5_driver_settings_writable(); status_t r5_driver_settings_read(const char* fileName, const char* key, BString& value); status_t r5_driver_settings_write(const char* fileName, const char* const* keys, int32 keyCount, const char* lines, bool replaceFile);

Driver settings: the files a driver reads with load_driver_settings(). The kernel reads them from the administrator's config/settings/kernel/drivers, not from the signed-in person's home, so these calls always use that folder. writable says whether this program may write there itself. read gives the text after key on its line, or B_NAME_NOT_FOUND. write replaces the lines that start with one of keys by lines and keeps the rest; with replaceFile the file is only lines. It writes a temporary file and renames it, so a crash never leaves an empty file. fileName is a name in that folder, without a slash.

status_t r5_admin_set_driver_setting(const char* fileName, const char* const* keys, int32 keyCount, const char* lines, bool replaceFile, BString& error);

The same write through Login, for a standard account with a grant. Login accepts only the settings it knows, today those of Media: the buffer size (play_buffer_frames, record_buffer_frames) in hda.settings and usb_audio, the USB channel layout, and virtual surround. Anything else is refused.

static const char* kKeys[] = { "channel_layout" };
BString error;
status_t status;
if (r5_driver_settings_writable()) {
	status = r5_driver_settings_write("usb_audio", kKeys, 1,
		"channel_layout 6\n", false);
} else {
	// Gray until r5_admin_change_allowed(); then Login writes it.
	status = r5_admin_set_driver_setting("usb_audio", kKeys, 1,
		"channel_layout 6\n", false, error);
}
#include <AdminLock.h>

BLayoutBuilder::Group<>(bottomRow, B_HORIZONTAL)
	.Add(fRevertButton)
	.AddGlue()
	.Add(new BAppearanceKit::BAdminLockBar());

bool administrator, unlocked;
if (r5_admin_query(administrator, unlocked) == B_OK && !unlocked)
	r5_admin_prompt_unlock(BMessenger(this));	// kMsgAdminLockChanged follows

BCard

class
Declared in<Card.h>
Derived fromBView
First userAbout R5

A rounded area with a group layout inside it. Use it for a heading or a summary that stands on its own. Children are added through GetLayout(), as with a BGroupView. A child that adopts its parent's colors, such as a BStringView, gets the card's face.

Use it for

A heading or summary in its own area: the About heading, the system information, an account summary, the Sign in header.

Not for

A form the user fills in: that stays on the panel. A stack of pages: that is Haiku's BCardView.

BCard(const char* name, card_style style = B_CARD_DOCUMENT, orientation orientation = B_VERTICAL);

B_CARD_DOCUMENT fills with the document background, B_CARD_PANEL with the panel color one step darker. The border is one pixel, the corner radius a quarter of the plain font size, the inner margin B_USE_BIG_SPACING.

void SetStyle(card_style style); card_style Style() const;

Changes the fill and the color children adopt.

#include <Card.h>

BAppearanceKit::BCard* card = new BAppearanceKit::BCard("info",
	BAppearanceKit::B_CARD_PANEL);
BLayoutBuilder::Group<>((BGroupLayout*)card->GetLayout())
	.Add(new BStringView("title", "Processors"))
	.Add(new BStringView("value", "2"));

class

The heading card at the top of a page: a small category line (the eyebrow), the title, a description and an icon on the right. It draws itself and has no child views.

-1 when none is selected.

class

Derived fromBOutlineListView
First userSettings, beside the page

A list of categories that fold, with one category open at a time, and a filter for search. The rows are BSidebarItems: categories at the top level, pages under them with AddUnder(). Wrap it in a BScrollView.

Functions

<R5UI.h>
BRect r5_screen_draw(BView* view, BRect bounds, rgb_color contentColor);

The screen frame Settings uses, in a 4:3 shape centered in bounds, filled with contentColor. It returns that fill, in the view's coordinates, so the caller can draw a Deskbar or a notification on the glass.

void r5_screen_caption(BView* view, BRect content, const char* text, rgb_color textColor);

Window effects

<WindowEffects.h>

The shadow and the frosted glass of windows, shown in the GPU mode only. Free functions in BAppearanceKit, like ui_color(): each sends one message to app_server. In the CPU mode every call is accepted and stored and nothing changes on screen. B_TRANSPARENT_COLOR keeps meaning "do not erase" and never becomes glass. First user: the "Window effects" box on Look and feel, in Settings and in the Appearance program.

uint32 window_effects(); status_t set_window_effects(uint32 effects);

The user's choice of B_WINDOW_SHADOW, B_WINDOW_FROSTED_GLASS and B_WINDOW_ANIMATIONS, for the whole desktop. app_server keeps it with its other appearance settings. Only Settings and the Appearance program set it.

enum window_effect_strength window_effect_strength(); status_t set_window_effect_strength(enum window_effect_strength strength);

One step for the shadow and the glass: B_WINDOW_EFFECTS_QUIET, B_WINDOW_EFFECTS_BALANCED (the default) or B_WINDOW_EFFECTS_GLASSY. The function has the name of the type, as stat() has that of struct stat, so the type is written enum window_effect_strength.

status_t set_window_glass(BWindow* window, bool glass); status_t set_view_glass(BView* view, bool glass);

A program asks for glass behind its own content. The view's background is drawn with alpha 0 and the blur behind the window shows through. What the view draws with B_OP_ALPHA and B_ALPHA_COMPOSITE keeps its alpha; every other mode stays opaque. The view must be attached and its window locked.

#include <WindowEffects.h>

MyWindow::MyWindow()
	: BWindow(BRect(100, 100, 500, 400), "Glass", B_TITLED_WINDOW, 0)
{
	BAppearanceKit::set_window_glass(this, true);
}
