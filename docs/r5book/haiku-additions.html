Additions to Haiku kits

Public calls R5 added to classes that Haiku already has. The rest of each class is as the Haiku Book describes it. A program that uses one of these calls runs on R5, not on Haiku.

Check before you call. These calls are not in Haiku. A program that should also run on Haiku keeps its own fallback, or builds this part only for R5.

BFormattingConventions::CoerceFormatForClock()

Locale Kit
Declared in<FormattingConventions.h>
Librarylibbe.so
Haiku BookBFormattingConventions
void CoerceFormatForClock(BString& outFormat) const;

Rewrites a time pattern so it follows the user's 12- or 24-hour choice. With the 24-hour clock it also rewrites a 12-hour pattern that has no AM/PM marker. With the 12-hour clock it adds AM/PM only when the pattern has none.

Use it when you build or store your own ICU time pattern. A pattern you store yourself is not adjusted later, so a clock that saved an English pattern kept showing 12 hours after the user chose 24. Haiku's GetTimeFormat() already applies the choice; this call does the same for your own pattern.

BFormattingConventions conventions;
BLocale::Default()->GetFormattingConventions(&conventions);

BString pattern("h:mm");
conventions.CoerceFormatForClock(pattern);	// a 24-hour pattern when the user chose 24 hours

BLocaleRoster::ApplySettings()

Locale Kit
Declared in<LocaleRoster.h>
Librarylibbe.so
Haiku BookBLocaleRoster
status_t ApplySettings(const BMessage* message);

Applies one B_LOCALE_CHANGED message on top of the settings file. A field that is not in the message keeps its value.

Haiku's Refresh() rereads the settings file. On R5 the Locale preferences broadcast a change even when the file could not be written, for example when another account owns it. A running program that only calls Refresh() would then keep the old language, country or clock. Call ApplySettings() after Refresh(), so the message wins over a stale file. Deskbar, Tracker and the audio mixer do this.

void
MyApp::MessageReceived(BMessage* message)
{
	if (message->what == B_LOCALE_CHANGED) {
		BLocaleRoster::Default()->Refresh();
		BLocaleRoster::Default()->ApplySettings(message);
		// redraw anything that shows a date, a time or a number
		return;
	}
	BApplication::MessageReceived(message);
}

Decorator hooks and the decorator ABI version

Decorators (app_server add-ons)
Declared insrc/servers/app/decorator/Decorator.h (private to app_server)
Installed in/system/add-ons/decorators
ForDecorator add-ons, not applications
First userThe R5 decorator (R5 2026.1, M11 step 1)

A decorator draws the window frame: the tab, the buttons and the border. It is an add-on that subclasses Haiku's Decorator and exports instantiate_decor_addon(), as on Haiku. Applications do not see any of this; they keep talking to app_server through BWindow.

R5 adds three hooks at the end of Decorator. Each has a default, so a decorator only overrides the ones it needs. The rectangles hold a width per side, not a position.

virtual void GetShadowExtent(BRect* extent);

How far the window shadow reaches past the border on each side. The default is a small shadow that falls down, derived from the border width. The shadow is drawn only when windows are composed on the GPU; until then the value is unused.

virtual void GetGlassRegion(BRegion* region);

The part of the frame, in screen coordinates, that is frosted glass when windows are composed on the GPU. The default is empty: no glass.

virtual void GetInputMargin(BRect* margin);

An area outside the border where the window can be resized, although nothing is drawn there. It is not part of the footprint, does not cover the windows below, and has no pixels. The default is 0 on every side. Return 0 for a side that cannot be resized (B_NOT_RESIZABLE, B_NOT_H_RESIZABLE, B_NOT_V_RESIZABLE), and classify the margin in RegionAt() as a border or a corner.

bool InputMarginContains(BPoint where);

Not a hook: whether where lies in the input margin, outside the border. app_server uses it to find the window under the mouse.

The ABI version

The hooks change the layout of Decorator, so an add-on built before them would crash app_server. Every decorator add-on therefore exports the ABI version it was built with. Put R5_DECORATOR_ABI_EXPORT in one source file of the add-on. app_server loads only an add-on with the current version (R5_DECORATOR_ABI_VERSION, now 1). Any other add-on is refused with one line in the syslog, and the default decorator is used:

app_server: decorator OldDecorator refused: abi 0, need 1

Rebuild an old decorator against the R5 headers to fix that. A new hook comes after these three, and the version goes up by one.

Resizing by the edge

On R5, dragging a border or a corner with the primary button resizes the window on that side, with every decorator, and the resize cursor shows while the mouse is over it. Dragging the tab moves the window. A window that cannot be resized in that direction is moved, as on Haiku.

#include "DecorManager.h"
#include "SATDecorator.h"

class MyDecorator : public SATDecorator {
public:
	MyDecorator(DesktopSettings& settings, BRect frame, Desktop* desktop)
		: SATDecorator(settings, frame, desktop) {}

	virtual void GetGlassRegion(BRegion* region)
	{
		region->MakeEmpty();
		region->Include(&fTabsRegion);	// the tab is glass
	}
};

class MyDecorAddOn : public DecorAddOn {
public:
	MyDecorAddOn(image_id id, const char* name) : DecorAddOn(id, name) {}

protected:
	virtual Decorator* _AllocateDecorator(DesktopSettings& settings,
		BRect rect, Desktop* desktop)
	{
		return new (std::nothrow) MyDecorator(settings, rect, desktop);
	}
};

R5_DECORATOR_ABI_EXPORT	// without it, app_server refuses the add-on

extern "C" DecorAddOn*
instantiate_decor_addon(image_id id, const char* name)
{
	return new (std::nothrow) MyDecorAddOn(id, name);
}

B_USB_IOCTL_GET_DEVICE_SPEED

USB (drivers)
Declared in<usb/R5USBSpeed.h>
Modulebus_managers/usb (USB module v3)
ForKernel drivers

Haiku's USB module does not tell a driver at which speed its device runs. R5 answers that through the existing usb_ioctl() of the module; the module structure is unchanged. The value is one of B_USB_SPEED_LOW, _FULL, _HIGH, _SUPER and _SUPER_PLUS. A USB audio driver needs it to size its packets: a high-speed device takes eight packets per millisecond, a full-speed device one.

status_t usb_ioctl(B_USB_IOCTL_GET_DEVICE_SPEED, uint32* value, sizeof(uint32));

In: the usb_device in *value. Out: its speed. B_BAD_VALUE when the ID is not a device. On Haiku, and on R5 before build 10058, the call returns B_DEV_INVALID_IOCTL; keep a fallback.

uint32 speed = (uint32)device;
bool highSpeed;
if (gUSBModule->usb_ioctl(B_USB_IOCTL_GET_DEVICE_SPEED, &speed,
		sizeof(speed)) == B_OK)
	highSpeed = speed >= B_USB_SPEED_HIGH;
else
	highSpeed = guess_from_descriptors();	// your own fallback
