R5Book

Building on LibR5

The R5Book describes the libraries R5 adds next to libbe: what each part looks like, what it is for, and how to call it. It follows the Be Book: one entry per class, with where it is declared, what it derives from, and its member functions.

Pictures. The pictures in this edition are HTML mockups, drawn with the R5 system colors and sizes at the 12 point system font. They will be replaced by screenshots taken from R5 itself. Each picture says which one it is.

The kits

libr5icons.so · <R5Icons.h>

Icons Kit

Haiku's own icons as bitmaps, icon buttons that match a text button, and line glyphs such as power, restart and the password eye, drawn in the text color.

 libr5ui.so · namespace BAppearanceKit

Appearance Kit

Cards, page headings, the Settings sidebar, the screen picture, account cards and lists, the password field, the accent button, and the icon view.

 libmidi2.so · <Midi2Defs.h>

MIDI 2 Kit

MIDI 2.0 in Haiku's own MIDI kit: the Universal MIDI Packet, 16-bit velocities and 32-bit controllers, Property Exchange, Profiles and endpoint discovery.

Vulkan in a window

Draw with Vulkan into an ordinary BView, on the GPU or in software, with R5's own extension, registered with Khronos.

Next to libbe, not inside it

A Haiku program that links only libbe keeps working, and keeps its ABI. LibR5 adds parts Haiku does not have; it does not rename or replace a libbe call. The classes follow the Haiku conventions: a B prefix, archiving with Archive() and Instantiate(), colors from ui_color(), and sizes that follow the system font.

Rules for LibR5

  • Additive. A new function or class is added at the end. A function that shipped keeps its arguments. A numbered value, such as R5_ICON_HOME, keeps its number.
  • MIT. The libraries and their headers are MIT, so any program can link them. Code added to them must be MIT-compatible.
  • Shared. A helper written for R5 and used by more than one program goes in one of these libraries, with its entry in this book and in docs/LIBR5.md in the same change.
  • Sharp. An icon is rendered at the size it is shown and drawn pixel for pixel. Stretching a bitmap by even one pixel makes its edges jagged; use BIconView.
  • System colors. Every color comes from ui_color(), so a part follows the user's colors and dark mode.
