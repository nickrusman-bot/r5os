libmidi2.so

The MIDI 2 Kit

R5's libmidi2.so sends and receives the Universal MIDI Packet (UMP) of MIDI 2.0. The MIDI 1.0 calls stay; there is no second MIDI kit. Property Exchange, Profiles, per-note controllers, and Endpoint and Function Block discovery are in this same kit.

One kit, two protocols. A uchar velocity or controller is still a MIDI 1.0 message. The wide values have their own calls with a 2 at the end, so a bare integer always picks the MIDI 1.0 call.

MIDI 2.0 additions
Declared in<MidiProducer.h>
Derived fromBMidiProducer

The Haiku producer, with three calls added. Each sends one MIDI 2.0 packet; connected consumers that only know MIDI 1.0 still get their 7-bit hooks.

void SprayNoteOn2(uchar channel, uchar note, uint16 velocity, bigtime_t time = 0) const;

A note-on with a 16-bit velocity, as one type 0x4 channel-voice packet.

void SprayControlChange2(uchar channel, uchar controller, uint32 value, bigtime_t time = 0) const;

A control change with a 32-bit value.

status_t SprayUMP(const uint32* ump, size_t wordCount, bigtime_t time = 0) const;

Any packet. wordCount is 1, 2 or 4 and must match the message type in ump[0]; anything else is refused.

producer->SprayNoteOn(0, 60, 100);						// MIDI 1.0

uint16 velocity = 0x8000;
producer->SprayNoteOn2(0, 60, velocity);				// MIDI 2.0

uint32 level = 0x80000000;
producer->SprayControlChange2(0, B_MAIN_VOLUME, level);

uint32 words[2];
midi2_encode_note_on(0, 60, velocity, words);
status_t status = producer->SprayUMP(words, 2);

The Universal MIDI Packet

<Midi2Defs.h>

A packet is one, two or four 32-bit words, native byte order. The message type in the top four bits of the first word says how many.

TypeWordsIn this kit
0x0 utility, 0x1 system, 0x2 MIDI 1.0 channel voice1A type 0x2 packet is unpacked to the MIDI 1.0 hooks. SprayUMP accepts type 0x1.
0x3 SysEx7, 0x4 MIDI 2.0 channel voice2Type 0x4 note and control keep the full value and also call the 7-bit hooks. Type 0x3 calls SystemExclusive once the message is complete.
0x5 data, 0xD Flex Data, 0xF stream4Delivered in Data; no extra hook reads it.
anything else—Refused by SprayUMP and midi2_ump_from_payload.
uint32 midi2_ump_word_count(uint32 firstWord);

1, 2 or 4, or 0 for a type the kit does not take.

void midi2_encode_note_on(uchar channel, uchar note, uint16 velocity, uint32 words[2]); void midi2_encode_control_change(uchar channel, uchar controller, uint32 value, uint32 words[2]);
uint16 midi2_scale_up_7_to_16(uint8 value7); uint8 midi2_note_on_midi1_velocity(uint16 velocity);

Value scaling as in Appendix D of the specification. A 16-bit note-on velocity becomes at least 1 in MIDI 1.0, so it never turns into a note-off.

BMidiLocalConsumer

reading a packet
Declared in<MidiConsumer.h>
Derived fromBMidiConsumer

Data() gets the packet. The base Data() still calls NoteOn, ControlChange and the other 7-bit hooks, and SystemExclusive for a complete SysEx7. To read the full value, override Data(), unpack the words, and return without calling the base when you handled it.

void
MyConsumer::Data(uchar* data, size_t length, bool atomic, bigtime_t time)
{
	uint32 words[4];
	size_t count = 0;
	if (midi2_ump_from_payload(data, length, words, 4, &count) == B_OK) {
		if (midi2_is_note(words, count)) {
			uint16 velocity = midi2_note_velocity(words, count);
			// ...
		}
		return;
	}
	BMidiLocalConsumer::Data(data, length, atomic, time);
}
status_t midi2_ump_from_payload(const void* data, size_t length, uint32* words, size_t capacity, size_t* _count);

Checks the magic (B_MIDI2_UMP_MAGIC), the word count, the buffer length and the message type, then copies the words.

bool midi2_is_note(const uint32* words, size_t wordCount); uint16 midi2_note_velocity(const uint32* words, size_t wordCount); bool midi2_is_control(const uint32* words, size_t wordCount); uint32 midi2_control_value(const uint32* words, size_t wordCount);
size_t midi2_sysex_packet_count(size_t length); status_t midi2_encode_sysex(const uint8* data, size_t length, uint32* words, ...); status_t midi2_sysex_payload(const uint32* words, size_t wordCount, uint8* _status, ...);

SysEx7 in type 0x3 packets: status 0 is a whole message, 1 starts, 2 continues, 3 ends. The kit joins the parts per consumer and per group.

Property Exchange

<Midi2Property.h>

MIDI-CI Property Exchange: get and set a device's properties as JSON, over SysEx. The kit encodes and decodes the messages, splits a large body into chunks and joins them again, and answers inquiries from a small local catalog (DeviceInfo, ChannelList, ProgramList, CtrlMapList).

Endpoint and Function Block discovery

<Midi2Stream.h>

UMP Stream messages (type 0xF, four words) ask a MIDI 2.0 endpoint who it is, what its function blocks are, and which protocol to use. The local endpoint is named R5, with one bidirectional function block on group 0. It runs MIDI 1.0 protocol until a Stream Configuration message selects another.

status_t midi2_stream_endpoint_discovery(uint8 filter, uint32 words[4]); status_t midi2_stream_block_discovery(uint8 block, uint8 filter, uint32 words[4]);

Filters: B_MIDI2_STREAM_FILTER_INFO, _IDENTITY, _NAME, _PRODUCT, _CONFIG. Block 0xFF asks for every block.

void midi2_endpoint_init(midi2_endpoint* endpoint); status_t midi2_stream_configure(midi2_endpoint* endpoint, const uint32* request); midi2_stream_identity(...), midi2_stream_reply(...)

Who the endpoint says it is comes from your program's identity.

Your program's identity

<Midi2Identity.h>

A MIDI 2.0 program that answers discovery or Property Exchange tells the other side who made it: a manufacturer SysEx ID, a family, a model and a revision. That identity is your program's, not R5's. R5 itself never presents itself to a MIDI device.

midi2_endpoint_init and midi2_pe_catalog_init start with B_MIDI2_NONCOMMERCIAL_ID (0x7D), the ID for educational and non-commercial use. A free hobby program may keep it. A program that is published, by a company or for sale, sets its own SysEx ID from the MIDI Association.

struct midi2_identity { uint8 manufacturer[3]; // { id, 0, 0 } or { 0x00, b1, b2 }, 7-bit bytes uint8 family[2], model[2], revision[4]; const char* manufacturerName, *familyName, *modelName, *versionName; };

The names go into the DeviceInfo resource. They may not contain ", \ or control characters; NULL is an empty name.

status_t midi2_endpoint_set_identity(midi2_endpoint* endpoint, const midi2_identity* identity, const char* name, const char* productId);

Sets the UMP Device Identity, and the endpoint name and product instance ID unless they are NULL (cut to 14 characters). B_BAD_VALUE for a byte above 0x7F.

status_t midi2_pe_catalog_set_identity(midi2_pe_catalog* catalog, const midi2_identity* identity);

Writes the DeviceInfo resource of a Property Exchange catalog. B_BAD_VALUE for a byte above 0x7F, a name that would need escaping, or a result that does not fit.

midi2_identity identity = {};
identity.manufacturer[0] = 0x00;	// your three-byte SysEx ID
identity.manufacturer[1] = 0x21;
identity.manufacturer[2] = 0x09;
identity.model[0] = 3;
identity.manufacturerName = "Example";
identity.modelName = "Synth";
identity.versionName = "1.2";

midi2_endpoint endpoint;
midi2_endpoint_init(&endpoint);
midi2_endpoint_set_identity(&endpoint, &identity, "Example Synth", NULL);

midi2_pe_catalog catalog;
midi2_pe_catalog_init(&catalog);
midi2_pe_catalog_set_identity(&catalog, &identity);

USB MIDI 2.0 descriptors

<Midi2Usb.h>

Write and read the USB descriptors of a MIDI 2.0 interface: the standard interface descriptor, the class-specific header (version 2.0), and a Group Terminal Block (type 0x26, subtype 0x02; 0x01 is the header in front of the blocks). Alternate setting 0 is the MIDI 1.0 interface; a later one is MIDI 2.0. usb_midi selects that MIDI 2.0 alternate when a device has one, and reads the Group Terminal Blocks from the device with a GET_DESCRIPTOR request, since they are not in the configuration descriptor. Each group becomes one port.

status_t midi2_usb_write_interface(...); status_t midi2_usb_parse_interface(...); status_t midi2_usb_write_header(...); status_t midi2_usb_parse_header(...); status_t midi2_usb_write_group_terminal(...); status_t midi2_usb_parse_group_terminal(...);

For driver writers

<midi_driver.h>

midi_server sends a packet with ioctl(fd, B_MIDI_WRITE_UMP, &packet) and reads one with B_MIDI_READ_UMP. The argument is midi_ump_packet: word_count and words[4]. A driver that does not implement them is used as a MIDI 1.0 port, with read() and write(), as before.
